# AFTERLIGHT — ตรอกนิรันดร์

Current version: **2.2.1**. See [CHANGELOG.md](CHANGELOG.md).

A small Three.js exploration game. Calico V2.2 replaces the assembled primitive cat
with a continuous sculpted mesh, vertex-painted calico markings, fur geometry,
slim harness, and an articulated GLB hierarchy. It is a game-style approximation
of the character reference, not a photorealistic reconstruction.

## Run

Serve the repository root (`python -m http.server 8000`) and open
`http://localhost:8000`. Internet access is required for the pinned Three.js CDN
imports. Azure Static Web Apps serves `index.html` and the `assets/` directory.

WASD: walk; Shift: run; Space: jump; E: interact; Q: meow; F: rest;
C: inspect the cat; Esc: return; drag: orbit; wheel: zoom.

## Model source

`assets/calico-v2.glb` is generated by `tools/build_cat.py` (Python + NumPy).
It has named transform joints for the head, eyes, ears, legs, whiskers and tail,
and portable Walk / Run animation clips. The game drives the named joints directly;
it does not simultaneously play those clips. The tail uses a skin-weighted continuous mesh; the body and limbs use articulated transform nodes. `tools/render_cat.py` (NumPy + Pillow) renders
actual mesh geometry for inspection without WebGL. Its lighting is a software
approximation, so the review image is not a screenshot of the running game.

```sh
python tools/build_cat.py
python tools/render_cat.py
python tools/make_preview.py /path/to/afterlight-calico-v2-preview.html
```

The standalone review file embeds the same GLB bytes, allowing the model to load
without a separate local asset fetch. Three.js still requires internet access.

The soft-face revision uses shallow eye surfaces fitted to the actual cheek contour,
blended almond-shaped eyelids, and a smaller continuous muzzle. Eye surfaces rise
at most 4 mm above the face; pupils are painted into that surface, not separate balls.

## Mobile browsers and local saves

On touch devices, use the left joystick to walk, toggle **วิ่ง** to run, and use
buttons to jump, meow, interact, rest or inspect the cat. Drag the scene to orbit;
pinch with two fingers to zoom, including while another finger holds the joystick.
The menu also offers zoom, journal, manual save and return to the entrance.
Controls adapt to portrait/landscape and screen safe areas. Touch devices use a
pixel ratio capped at 1 with an adaptive pixel budget, 1024 px shadows and direct antialiased rendering without bloom.
Keyboard and mouse controls remain available.

Progress saves every five seconds, when discovering a story, when resting or
returning to the entrance, and when hiding/leaving the page. **เล่นต่อ** restores
the latest grounded position, facing direction, normal camera, discovered stories
and resting state. An airborne save resumes at the last grounded checkpoint;
an obstructed/unsupported checkpoint returns to the entrance and retains stories.
Dialogue reading position and transient input are not restored. **เริ่มใหม่** on
the cover asks before replacing an existing save.

Saves use `localStorage` (`afterlight.save.v1`) on the same device, browser and
site origin. They do not sync across devices. Clearing website data deletes them;
private browsing may discard them. Browser storage errors appear in the HUD,
and invalid/future-version saves are rejected without crashing the game.
Opening the cover alone never overwrites a save. A standalone downloaded preview
has separate browser storage from the Azure site; test persistent saves through
HTTP(S), as `file:` storage behavior varies by browser.

Deploy `index.html`, `assets/mobile.css`, `assets/game-support.js` and `assets/calico-v2/`
together. No backend or installation is needed. Three.js still loads from its CDN.

```sh
node tools/test_game_support.cjs
node tools/test_model_parts.cjs
python tools/make_preview.py /path/to/afterlight-mobile-save-preview.html
```

The Node tests cover storage validation, reload, unavailable/full storage,
multitouch input, pinch, cancellation, checkpoint restoration and lifecycle saves.
They do not exercise WebGL or real browser layout. Before publishing, check mobile
Safari and Chrome in both orientations, moving while rotating/jumping, journal
scrolling, and reopening the same URL to continue. Real-device rendering and frame
rate have not yet been verified for this revision.

## Flowing tail revision

The old seven rigid tubes are replaced by one tapered, rounded surface with 12
skin joints and fine coat strands weighted to the same skeleton. The game blends
small bends from base to tip, lowers the tail while running, and eases it into a
sideways resting pose. Integrated wave phase and exponential blending prevent
abrupt gait transitions. The facial geometry is unchanged.

`tools/tail_geometry.py` builds the tail as part of `tools/build_cat.py`.
`AfterlightSupport.tailPose` in `assets/game-support.js` supplies the motion.
The CPU renderer supports the actual GLB skin, and `tools/review_tail.py` exports
a software animation using the same pose function (not a gameplay recording).

```sh
python tools/test_tail.py
python tools/review_tail.py
```

Skin weights and 60 idle/running/resting poses were checked for finite deformation,
connected surface rings and floor clearance. Browser WebGL rendering remains to
be reviewed; these checks do not replace a real-device gameplay test.

The deployed GLB is stored losslessly as `assets/calico-v2/part-*.bin` with a
manifest. The loader fetches up to four parts concurrently and assembles the
original GLB before parsing. `tools/model_parts.py` verifies the combined SHA-256.
The full generated GLB and review images are local build outputs excluded from Git.

## Smooth motion revision (2.2.1, pending publication)

- Movement uses a 60 Hz simulation with interpolation between snapshots. Normal
  low frame rates no longer discard time at a 33 ms cap; pauses have a bounded
  100 ms catch-up budget. Saves use the simulation pose, never an interpolated one.
- The camera follows the interpolated horizontal position and damps height, orbit
  and zoom. Collision changes no longer trigger distance-based position snaps;
  a short hold prevents alternating wall-edge hits from pumping the camera.
- Mobile renders directly to the antialiased canvas. Desktop bloom uses an MSAA
  target when supported by the selected texture format. Both modes have capped
  pixel budgets and an automatic three-level quality governor with cooldowns.
  Sustained load lowers resolution and bypasses bloom; sustained recovery restores
  quality. Distant fine fur is hidden with hysteresis to reduce subpixel shimmer.
- Mobile address-bar height changes do not cancel held joystick input.

```sh
node tools/test_motion.cjs
node tools/test_game_support.cjs
node tools/test_model_parts.cjs
```

Motion tests execute the actual game movement and camera functions with vector/ray
test doubles. They compare 30/60/120/144 Hz and uneven frame intervals, collisions,
jumps, wall-edge camera behavior and quality transitions. This is not a browser
frame-rate benchmark; device FPS and WebGL/MSAA appearance still need live testing.

### Combined movement controls

Mobile Run and Jump now respond on `pointerdown`, including non-primary fingers.
Each button owns its pointer capture independently from the movement joystick and
camera. Synthesized clicks cannot repeat an action. Run remains a toggle (วิ่ง: เปิด),
so two thumbs can steer and jump continuously without holding a third button.
Keyboard W/arrow movement + Shift + Space also works when a game button had focus.
Jump requests allow a 120 ms landing buffer and a 90 ms ledge grace period, with no
midair double jump. Blur and modal transitions clear all pending input.

`node tools/test_combined_input.cjs` executes the actual action bindings, keyboard
handler, movement and collision functions with simulated pointer events. It checks
three simultaneous fingers, two-thumb play, release/cancel, duplicate clicks, and
the level's three crates and 2.65 m balcony. Device/browser multitouch behavior
still needs hands-on verification; these are code-level regression tests.
